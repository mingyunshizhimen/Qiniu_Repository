# 08 语音播报开关设计

## 1. 目标

为实时同声传译工作台增加一个“语音播报”开关。默认只展示双语字幕；用户手动开启后，译文确认才进入播报队列并播放语音。这样既保留纯文本演示的稳定性，也能在需要时展示更完整的同传效果。

## 2. 设计原则

- 默认不打扰用户，页面打开即为纯文本字幕模式。
- 播报能力是可选项，不影响字幕主链路。
- 无 API Key 时仍可运行，使用浏览器语音合成兜底。
- 有 API Key 时优先使用后端 TTS，保证播报效果更自然。
- 播放失败时自动降级或静默，不阻塞字幕显示。

## 3. 交互方式

工作台中增加一个滑动开关，语义为“语音播报：开 / 关”。

- 关闭时，仅显示原文与译文字幕，不进行语音播报。
- 开启时，译文确认后进入播报队列，按顺序播放。
- 播放中显示轻量状态，但不遮挡字幕区域。
- 用户随时可关闭播报，关闭后停止后续排队播放。

## 4. 技术方案

推荐采用双方案兼容：

1. 浏览器语音合成兜底
   - 适合无 Key 环境。
   - 不依赖额外后端服务。
   - 优点是开箱即用，缺点是音色和稳定性依赖浏览器实现。

2. 后端百炼 TTS
   - 适合有 `DASHSCOPE_API_KEY` 的环境。
   - 由后端统一调用 TTS 服务，再把音频发给前端播放。
   - 优点是效果更自然，缺点是多一层网络依赖。

前端只消费播报状态和音频播放结果，不直接绑定具体 TTS 提供方。

## 5. 事件与数据流

```text
transcript.final
→ semantic_unit.final
→ translation.final
→ (if switch on) enqueue speech
→ browser TTS or backend TTS
→ playback started / finished / failed
```

建议增加轻量播报状态：

- `speech.enabled`
- `speech.disabled`
- `speech.playing`
- `speech.idle`
- `speech.failed`

## 6. 错误处理

- TTS 不可用时不影响字幕继续显示。
- 后端 TTS 失败时自动回退浏览器 TTS，或静默降级。
- 浏览器不支持语音合成时，播报开关仍可打开，但只保留字幕并提示降级。
- 用户关闭开关时，清空未播放队列。

## 7. 测试方式

- 验证开关默认关闭，页面只显示字幕。
- 验证打开开关后，译文确认会进入播报队列。
- 验证无 API Key 时浏览器兜底仍可播报。
- 验证后端 TTS 失败时会降级且不影响字幕。
- 验证关闭开关会停止后续播报。

## 8. 范围边界

本 PR 只做工作台内的语音播报开关与播报链路接入，不新增独立播报页面，不做术语库、不做上下文记忆、不做回溯纠错。
